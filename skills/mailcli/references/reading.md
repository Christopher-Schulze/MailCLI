# Reading, search, and attachments

- Local index reads work while Mail is closed. They never prove that a message is absent from the server or delivered, and they never poll for new mail; [Sync](mutations.md) separates observing counts from requesting a Mail sync.
- `messages list` shows the newest-first unified inbox. `--mailbox` takes a ref, a case-insensitive role (`inbox`, `sent`, `drafts`, `trash`, `junk`, `archive`) or an exact slash path, and `messages filter` and `messages search` take the same values. A role there covers every account unless `--account` is given, while `list` needs `--account` or a ref when several accounts match. For an ambiguous role choose one of the returned refs or accounts. Reads need a supported store and never scan through Apple Events, so read all mail by paging each mailbox.
- Degraded, stale or ambiguous account coverage blocks transport. Check `complete`, `identity_coverage`, `direct_ops_supported` and `reason`; an unsupported provider needs [setup](setup.md) with explicit hosts.
- Follow `page.next_cursor` until it is absent. A page that overflows the output budget returns no rows and no new cursor. A cursor is bound to its store and query (catalog cursors to their command, scope and ordered refs), so restart when one is invalid, and refresh refs after a copy, move, delete or sync.
- `--fields` returns `ref` plus the named selectors (`mailbox_ref` and `account` only when named), and `all` alone keeps the defaults; an invalid selector fails before any read. List rows carry `ref` directly, while search and filter rows nest it under `summary`.
- A Message-ID candidate must match exactly one normalized header; a missing, malformed, substring or duplicate match fails with `imap_ambiguous_message_id` before any hydration or mutation.
- `messages get` defaults to metadata read from bounded headers only: `summary`, `to`, `cc`, `bcc` and `reply_to`, without attachments or completeness. A missing local copy may hydrate the HEADER, never the body. `--view plain` adds the normalized text, attachments and completeness, and `--view raw` is the exact RFC source. `--links host` shortens long URLs to their host, `none` removes them and `full` keeps them; use `host` for triage and summaries. Exports are always complete, and batch items accept `links` too. Require `content_complete` and check `missing_parts`, `source` and `hydration`; partial content is evidence only.
- Listing attachments scans bounded MIME metadata and hydrates an incomplete source only when needed. A directory holds at most 10,000 entries, 128 ambiguity hashes and 1 GiB of hash input, and `attachment_resource_limit` never proves completeness or a download.
- `messages thread` follows the local conversation, not RFC threading. The seed page is chronological with NULL dates first and excludes deleted or inactive messages. Repeat the same REF with `prev_cursor` for older or `next_cursor` for newer members; `truncated` means more exist. An insert behind the boundary may require a restart.
- `messages new` lists the newest server messages of the inbox (or `--mailbox`) that the local store lacks, newest first, from headers only; it needs stored credentials and changes nothing. Read a row through its `server_ref` with `messages get`, `messages raw` or `attachments`, which read over IMAP without marking it read; `summary.local_ref` appears once the store has the message. Batch `read` and `attachment_save` items accept it too; every other command rejects a server ref. `truncated:true` means more exist, and a mailbox with state `uidvalidity_changed` or `unresolved` returns no rows. `sync` lets Mail.app bring the rows into the store.
- Every search page reports exactness, partial and missing results and bounds; completeness needs `data.page.coverage.complete` on the terminal page and no earlier gap. When no progress is possible the error is `search_budget_too_small` with `error.required_bytes` in whole MiB and no new cursor: raise `--max-scan-bytes` through the recovery args and keep the incoming cursor, query and filters. An old or stale token restarts, and an index change invalidates progress and coverage.
- `--with-threading` fills `summary.in_reply_to[]` and `summary.references[]` (bracketed Message-IDs, in order), `from{name,address}` and `threading_complete`. `--with-excerpt` fills `excerpt`, `excerpt_complete` and `excerpt_source` (`local`, `imap-partial` or `unavailable`) from at most 256 KiB of local source or, over IMAP, the MIME headers plus a 64 KiB text prefix in one FETCH per mailbox, never a full FETCH; IMAP excerpts are cached locally for 30 days. Empty or false means unknown, not absence. `messages get` takes `--fields excerpt,header_fields`.
- A failed enrichment puts its first error code in `summary.enrichment_error` (for example `imap_timeout`) while the page still succeeds. `enrichment_page_budget_exhausted` means the page read 8 MiB of excerpt source; those rows keep their reply metadata, so fetch their excerpts on a smaller page.
- `--after` is inclusive and `--before` exclusive on the received date; a date-only value means local midnight, and the exact strings stay bound to the cursor.
- Save attachments only by opaque attachment ID to new absolute 0600 files, then verify size and SHA-256. A retained `saved_attachment` needs a path and hash inspection, and a complete or unknown publication forbids replay ([Recovery](output-and-recovery.md)).
- Unnamed message/rfc822, message/global and multipart-digest embeds count as attachments; save the selected original MIME. Nested text does not appear in the outer body or in search. A hash proves the bytes, not the validity of the message.
