# Local drafts and reviewed revisions

Create or edit a local draft first, inspect it, and obtain explicit user authorization before sending or destructive mutation.

Single-reference commands accept `--ref REF` or one positional `REF`, with options before or after it. Every supplied value must match. `--ref` is canonical for scripts and recovery; normalization preserves the route's reference kind, so `drafts open/adopt` still take Mail.app message refs and other draft commands take local draft refs.

- Draft-list and preview JSON defaults to 1 MiB; `--max-bytes` raises the complete-envelope limit through 64 MiB. `drafts list --fields` accepts comma-separated combinations of `age_days`, `created_at`, and `updated_at`; `all` must stand alone. Fixed core fields retain refs, subject/recipient review data, account and format metadata, send/save/handoff state, and page revision/cursor. `state_error` remains conditional corruption evidence. Capabilities expose the accepted selectors plus separate `draft_list_core_fields` and `draft_list_optional_fields`. `drafts preview` returns its complete body or `output_too_large` with `drafts inspect --ref REF --view full --export /absolute/new/path --json`; it never truncates.

- Rich drafts bound source, rendered Markdown, HTML, and plain text to 4 MiB each, parsed trees to 65,536 nodes and 512 levels, and accumulated link-label text to 16 MiB. Create/update/reply/forward return and persist loss diagnostics. On `invalid_argument`, simplify the named content and review its sanitized preview and loss diagnostics; never treat a rejected or canceled rendering as a saved draft.
- `drafts list --limit N [--cursor CURSOR] --json` returns reference-ordered `data.drafts`, defaults to 20 entries, and accepts 1 through 200. Follow `data.page.next_cursor` until absent; a changed draft directory returns `invalid_cursor` and requires restarting without the cursor. On `output_too_large`, structured recovery halves a limit above 1 and preserves the incoming cursor, selected fields, and any explicit `--max-bytes`; the error returns no summaries or page cursor. At limit 1 it gives correction guidance without an identical command. Inspect every `state_error`; bodies and confidential claim payloads are omitted. `data.page.revision` describes listing consistency only and cannot be used as `--expected-revision` for update or send.
- `drafts edit` has `audience:human`; agents use `drafts update --ref REF --expected-revision REVIEWED_REVISION --input - --json` with authorized JSON changes. Nonterminal stdin returns `interactive_required` before editor launch or candidate creation; its recovery supplies the real ref/revision. Review with `drafts inspect`/`preview` first. `drafts edit --json` sends both editor streams directly to stderr and reserves stdout for one envelope. Interactive editors require stdin and stderr on the same foreground controlling terminal; unsupported routing returns `editor_terminal_unavailable`. On `editor_failed`, `editor_canceled`, or edited-input validation/update failure, inspect `error.draft_editor` for the retained `candidate_path`, original revision, and available process exit/signal status. Review the current draft and candidate before an explicit update with the newly reviewed revision; never blindly replay. Human mode preserves separate stdout/stderr, and terminal ownership/settings are restored after editing.
- Draft and batch JSON accept one object up to 16 MiB. Use each exact-case schema key once, including nested recipient/item keys; duplicates, case aliases, unknown fields, and trailing documents return `invalid_input` before mutation or dispatch. Escaped spellings identify the same decoded key. Draft `attachments` contains path strings. Create, update, reply, forward, and editor output share this validation; preserve intentional empty fields and omission instead of guessing or canonicalizing rejected input. `drafts update` is a patch: omitted fields keep their stored values and explicit empty values clear them, so send only the fields that change. Clearing attachments requires an explicit `"attachments": []` in JSON; a `body_format` change requires a new `body`, while repeating the stored format preserves the body without resubmitting it.
- Review complete content from the create/update result requested with `--view full`, or use `drafts inspect --ref REF --view full --json` when review content is missing. Retain the supplied ref and `data.draft.revision`; a complete reviewed result needs no duplicate inspect. Create, update, edit, inspect, and preview expose the opaque revision; metadata-only views, truncated output and list summaries do not constitute content review. Pass the reviewed value as `--expected-revision REVISION` for update and send, including JSON-input updates. Never place it in the editable input document or infer it from current state. A changed account, recipient role/name/order, subject, body, threading, or attachment path/size/hash invalidates the review; operational timestamps do not.
- On `draft_revision_conflict`, inspect `error.draft_revision_conflict` for expected/current revisions and any retained editor `candidate_path`. Read the current full draft and candidate, explicitly merge when needed, then retry update with the newly reviewed revision and `--input CANDIDATE_PATH`. Never blindly reuse a revision from an error. Editor conflicts preserve both versions. Reviewed send replay must also match the claim/receipt's `draft_revision`; legacy evidence without one returns `draft_revision_unavailable` and is inspect/reconcile-only.
- `drafts open --ref MSG_REF --json` reads a store message/draft ref through the same retrieval and hydration path as `messages get`, without opening an editor. Local `draft_*` refs require `drafts inspect`/`preview`. Keep edits in the local draft. Close any editor before moving or deleting a draft and pass `--allow-draft`; delete also requires `--confirm`.
- `drafts adopt --ref MSG_REF --json` copies a persisted Mail.app draft into a new local `draft_*` ref with the full inspect/update/send/discard lifecycle; the original store draft is never modified. Attachment bytes are saved under the draft's own `<REF>.attachments` directory inside the draft root, limits match `drafts create`, and a draft without recipients adopts as-is (sending still requires at least one). On `adopt_source_incomplete`, open the draft in Mail.app first; per-attachment failures keep their typed codes. If publication started or staging remains, do not replay: run `drafts list --json`, inspect the new ref with `drafts inspect --ref REF --json` when present, and preserve retained staging artifacts.
- If create/update/edit/reply/forward returns `output_too_large` with `effect_certainty:"complete"`, the local mutation already succeeded. Keep the returned ref/revision and run the supplied `drafts.inspect` recovery command; never replay the mutation to obtain output. For local drafts, only inspection supports body export. A broken stdout cannot guarantee an envelope, so inspect existing state before any retry.
- `data.draft.handoff_attempt` retains the attempt ID, outcome, dispatch state and compact snapshot counts in metadata/full/custom inspection, body exports and output-size fallback. Use this evidence for explicit handoff reconciliation; narrowing `--fields` cannot hide it. Unknown outcomes still block replay, and confirmed/canceled attempts are absent after successful cleanup. Snapshot contents and internal paths are not part of this summary.
- `drafts prune` defaults to a dry run listing stale never-sent drafts, expired receipts and orphan artifact refs; `--confirm` performs the authorized cleanup. Human output distinguishes `would sweep artifacts` from actual `swept_artifacts`. Both output modes retain completed effects and failed refs on a nonzero partial failure; do not replay completed work blindly. Busy orphan refs are skipped, never reported as swept.
- Lock-owning draft operations pin the leased directory identity for the whole lifecycle. Root replacement cannot redirect draft, claim, spool, receipt, temporary, rename, or cleanup paths; `draft_lock_unsafe` or `draft_lock_changed` is terminal for that operation.
