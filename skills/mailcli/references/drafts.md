# Local drafts and reviewed revisions

Review a local create or update before any authorized send or destruction.

A draft ref is given as `--ref` or as a positional REF; when several are supplied they must all match. Open and adopt take store refs, every other command takes local refs, and scripts and recovery commands use `--ref`.

Reply and forward drafts take `from` from exactly one own source To/CC match, or the source account's only identity when there is no match. Multiple matches or malformed To/CC leave it unset. Reply-all excludes own email addresses and aliases only from automatic CC; explicit recipients win. Malformed source To/CC blocks automatic reply-all with `invalid_message_source` before draft creation, while ordinary reply and explicit CC remain usable. Local-part case stays distinct; domain case deduplicates. Draft views carry `from` and `send_blockers` (`from_missing`, `recipients_missing`); resolve every blocker (`--from ADDRESS` on update) before sending. Blockers are not part of the revision, and an empty list does not mean sendable: `drafts send` still validates and its errors decide.

- A preview never truncates. When a view overflows, run `drafts inspect --ref REF --view full --export /absolute/new/path --json`.
- Rich drafts are bounded (see the manual); review the persisted loss diagnostics and sanitization. A rejected or canceled render is not saved.
- A changed draft directory makes a list cursor fail with `invalid_cursor`, so restart. On an overflow the emitted recovery halves the limit and keeps the cursor, fields and budget; at limit 1 the request itself needs correction. Inspect `state_error`. A list page revision is never a review revision.
- Editing is human-only. Agents run `drafts update --ref REF --expected-revision REV --input - --json`. After a failed, canceled or invalid edit, `error.draft_editor` keeps the candidate, revision, exit code and signal: read the current draft and the candidate, merge explicitly, and send a newly reviewed update, never a blind replay.
- JSON input is one object of at most 16 MiB. Duplicate, aliased, unknown or trailing keys fail before any effect, and rejected input is never guessed. An omitted patch field keeps its value and an empty one clears it, so `attachments:[]` clears all attachments (given as path strings). A changed `body_format` needs a `body`.
- Review the complete `--view full` result or run `drafts inspect --ref REF --view full --json`; metadata, list and truncated output are not a review. Pass `data.draft.revision` (for a preview `data.draft_preview.revision`) as `--expected-revision`, never inside editable JSON. Changes to account, recipients, subject, body, threading or an attachment's path, size or hash invalidate the revision; timestamps do not.
- On a conflict read the full current draft and the candidate, merge, and update with the reviewed revision and `--input CANDIDATE_PATH`, never with the revision from the error. Claims and receipts must match `draft_revision`; a legacy draft with an unavailable revision allows inspect and reconcile only.
- Open hydrates a store ref without an editor; a local `draft_*` ref uses inspect or preview. Close editors before mark, move or delete, which need `--allow-draft`, and delete also `--confirm`.
- Adopt copies a store draft into a new local `draft_*` with managed attachments and leaves the original unchanged. A draft without recipients may be adopted but not sent. For an incomplete source open the Mail draft first. After a publication or staging failure do not replay: list and inspect the new ref and keep the staging.
- After a completed overflow keep the ref and revision, inspect, and never repeat the mutation. After a broken stdout inspect the state before any retry.
- `drafts prune` dry-runs stale never-sent drafts, expired receipts and orphans, and `--confirm` cleans up; a would-sweep count differs from `swept_artifacts`. A partial failure keeps its effects and failed refs, a busy draft is skipped, and completed work is never replayed. `draft_lock_unsafe` and a changed directory or lock identity are terminal.
