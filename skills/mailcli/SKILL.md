name: mailcli
description: Read, search, draft, reply, forward, send, save received attachments, organize, or synchronize email through the accounts already configured in the local macOS Mail app. Use whenever the user asks an agent to inspect or act on local Mail.app content or to send mail from a configured account; do not use for direct provider login or unrelated prose-only email writing.

# MailCLI

Use MailCLI as the single boundary to accounts already configured in macOS Mail. SMTP send and IMAP mailbox mutations use a Keychain credential selected by the sender identity binding; never ask the user to paste account passwords, app-specific passwords, OAuth tokens, or any other credentials into chat. Direct the user to `mailcli send setup` (see Send below). Reads reuse the authentication Mail.app already has.

## Discover capabilities

1. Locate the executable with `command -v mailcli`; in this repository, fall back to `./bin/mailcli` after running `./scripts/build/build.sh`.
2. Run `mailcli capabilities --json` and use only the returned command IDs plus the separately published bounded batch surface. Require top-level `ok:true`, envelope `schema_version:1`, `data.capabilities.schema_version:1`, and a compatible release. Never infer capabilities, confirmation, dependencies, or result states from help text. Respect the reported limits, especially `raw_mime_send:true`, `send_transport:"smtp"`, `mutation_transport:"imap"`, `imap_connections_per_account:2`, `maximum_imap_connections_per_account:8`, `supported_providers` (Gmail `gmail.com`/`googlemail.com`, iCloud `icloud.com`/`me.com`/`mac.com`), `unsupported_provider_code:"transport_unsupported_provider"`, scripted `compose_write:false`, `compose_attachment_write:false`, `visible_compose_handoff:true`, and `visible_attachment_handoff:true`.
   Each `commands[].schema` is the executable input contract: use its described flags, defaults, bounds, enum values, required markers, JSON fields, and incompatible-input constraints. For a small query, run `mailcli capabilities --command messages.search --json` or `mailcli capabilities --family messages --json`; `--scope ID_OR_FAMILY` is shorthand. The selectors are mutually exclusive, unknown values return `invalid_argument`, and scoped output retains effect, confirmation, dependency, and result-state metadata while returning only matching commands. The selected ID or family appears as `data.capabilities.scope`.
   For bounded batches, use the `limits.batch_operations` values (`read`, `attachment_save`, `mark`), `default_batch_concurrency`, `maximum_batch_concurrency`, `maximum_batch_items`, and `maximum_batch_input_bytes`; submit only explicit item IDs and refs.
3. Run `mailcli help` only when human-readable flag usage is needed.
4. Run `mailcli doctor --json` before commands that open the Mail store: accounts, mailboxes, messages list/filter/search/get/raw, attachments, `drafts open`, and `sync`. `drafts reconcile` needs the store only for legacy claims with an observation baseline; direct transport claims use IMAP and local claim state. Skip the store check for `send setup`, `drafts send`, and local draft create/list/inspect/preview/edit/update/handoff/discard/prune. It verifies strict read-only store access and reports the exact Full Disk Access remediation when needed. If automatic discovery finds a newer or duplicate Mail generation, stop on `ambiguous_mail_store_generation` or `unsupported_mail_store_schema`; inspect `PersistenceInfo.plist`, and library integrations may configure an exact validated `Config.MailStorePath` only when the intended `V10` directory is known. Add `--diagnostics` only when phase timings are needed; timings contain no subjects, bodies, addresses, attachment data, or paths. Use `mailcli doctor --live --json` only before an Apple Events operation; Mail must already be running. The live probe verifies the exact process and reads the Mail version through one Apple Event. It never creates, saves, or sends a message because Mail 16 can retain an invisible outgoing backend even after `close saving no`.
5. Prefer `--json`. Require exit code `0`, top-level `ok:true`, and `schema_version:1`; list, filter, and search results are under `data.page`. The sole successful nonzero result is `sync --check --require-complete`: exit `3` with `ok:true` means `data.sync_check.complete:false`, so report the typed failures and never claim the check completed. JSON configuration failures return one `ok:false` envelope with `error.code:"initialization_failed"` or a preserved typed initialization code. A teardown failure returns `data.finalization.state:"failed"` with `error.code:"finalization_failed"`; if the command succeeded, the top-level `ok` is false and the exit code is `1`, while existing command errors and confirmed operation evidence remain under `data`.

Use `mailcli update` only when the user asks to update MailCLI. Human mode shows progress and either `Updated mailcli...` or `Already up to date...`; `mailcli update --json` emits one non-animated envelope. The command restricts metadata, assets, manifests, signatures, and redirects to exact trusted GitHub hosts over HTTPS with the default port and at most 10 redirects, then verifies `SHA256SUMS` with the Ed25519 public key pinned in the installed binary before trusting its checksum. It updates both the binary and this skill. If canceled, it lets the installer's rollback trap run and removes its complete owned process group before returning.

Apple Events are used only by `doctor --live`, `sync` without `--check`, and the read-only fallback gateway (probe, account listing, message listing, and sync) when the store cannot open. Compose-save and mutation fallback methods are not available in production. SMTP send, direct transport-claim reconciliation, and IMAP mark/move/copy/delete do not use Apple Events and do not need Mail.app running. For those Apple Events paths, MailCLI serializes calls across local agent processes, verifies the exact Mail process identity, waits for its owned `osascript` leader, terminates residual owned process-group members, and verifies that the group is gone before returning. Never issue parallel raw `osascript` calls. `mail_busy` means the operation did not contact Mail; wait for the active operation and retry once. `mail_not_running` means ask the user to open Mail when the requested action needs Apple Events. `mail_recovery_required` is reserved for an incomplete Apple Events operation that could have mutated Mail; do not retry or send another live command until the user has quit and reopened Mail. Read, probe, sync, and Automation-denial failures do not create that state.

For direct IMAP work, treat `mailcli capabilities --json` field `limits.imap_operation_contract` as authoritative. Shared-account LIST, STATUS, SEARCH, and FETCH may overlap only within the advertised bounded pool; APPEND and mutations are exclusive per account, and CLOSE advances the acquisition generation, cancels prior pending waiters with `imap_timeout`, drains operations that already own a session, and closes the pooled sessions. Later operations reconnect. Separate library Client values do not coordinate cross-client mutations.

Each CLI invocation creates one direct transport graph and closes its IMAP pool after command execution; store-backed invocations close transport before the local store. Human-mode cleanup failures are reported on stderr. JSON teardown failures are merged into the single final envelope so an exit-1 result cannot retain unexplained `ok:true`, and existing command evidence remains available.

## Read

IMAP FETCH hydration is bounded and parser-based: consume each complete logical response across literal boundaries, accept UID and BODY attributes in either order, ignore unrelated flag-only updates, and fail closed on duplicate or contradictory BODY values. Message-ID resolution treats UID SEARCH as candidate discovery, verifies every candidate with a bounded `BODY.PEEK[HEADER.FIELDS (MESSAGE-ID)]` fetch, and accepts only exact normalized single-header matches; substring, missing, duplicate, or malformed headers never become hydration or mutation targets.

Resolve account and mailbox identifiers through list commands instead of guessing display names. IMAP LIST metadata preserves the exact server wire name, decoded display name and hierarchy path, hierarchy delimiter, special-use flags, and negotiated Modified UTF-7 or UTF-8 encoding; commands must use the preserved wire name. A NIL delimiter is a flat namespace, and only INBOX is case-insensitive. Traverse every returned mailbox when the user asks for all mail. Use pagination until no cursor remains. Request full bodies, raw MIME, or attachment data only when required; list results intentionally omit large content.

When a local EMLX source is missing, a message reference may still carry a catalog-to-server UID and mailbox mapping. MailCLI checks that mapping against the live local row and mailbox-local `Info.plist` UIDVALIDITY before fetching or mutating, then uses the UID directly. Without usable mapping evidence, it reads the local Message-ID or asks a transport with the optional resolver for one exact mailbox-scoped subject/sender search. That resolver fetches only `BODY.PEEK[HEADER.FIELDS (MESSAGE-ID SUBJECT FROM)]`, caps candidate discovery at 128 UIDs, and accepts exactly one metadata match; ambiguity, a renamed/missing mailbox, stale UIDVALIDITY, or insufficient evidence fails closed with `imap_ambiguous_message_id`, `imap_mailbox_not_found`, `stale_reference`, or `imap_message_uid_unknown` as applicable. It never scans the account or guesses a similar message. A successful hydration returns a summary reference carrying the verified UID and UIDVALIDITY.

Use `accounts list --json`, then `mailboxes list --account REF --json` when an account scope is useful. Mailbox results are deterministic: the complete account reference and account-relative path stay paired during sorting, so equal display names remain attached to the correct account and hierarchy. Inspect `data.complete`; `false` means one or more configured accounts are degraded but still listed. Inspect `data.identity_coverage_complete` and each account's `identity_coverage`: `bounded` means more Sent history exists outside the configured bound, `not_observed` means no sender was found within that bound, and `no_valid_sender` means the available history was exhausted without a valid sender. The default Sent-history bound is 2,000 messages; capability JSON exposes the hard maximum of 10,000 for library configuration, and MailCLI never scans unbounded history. The sender-history bound has no public CLI flag, so do not tell users to change it through MailCLI. Entries with `state:"degraded"` are unusable for sending or mutations and include a stable `degraded_reason` plus `degraded_remediation` - skip them for those flows instead of treating them as healthy. A degraded sender-identity account needs `mailcli send setup --from ADDRESS` or a prior successful send; cache, special-use, and sender-data issues use the remediation returned on the account. Mutation identity resolution reports `account_reference_corrupt`, `account_reference_version_unsupported`, or mixed `account_reference_invalid` for malformed catalog references, `account_disabled` for a disabled account, and `account_identity_missing` when no credential-backed sender identity is provable. Invalid references are identified only by short SHA-256 fingerprints in diagnostics. Resolve localized or nested folders with one exact server-provided path segment per flag, for example `mailboxes resolve --account REF --path Gesendet --json` or `--path Projects --path 2026`; the resolver returns the exact wire name for IMAP commands and keeps case-distinct folders separate outside INBOX. IMAP mutations and Sent mirroring resolve an exact account-relative path before a unique special-use mailbox and then an exact localized display-name fallback; multiple candidates fail with `imap_ambiguous_mailbox` and list their exact wire names, so use the exact path from mailbox listing/resolution or fix the duplicate server mapping before retrying. Use `messages list --mailbox REF --limit N --cursor CURSOR --json` for mailbox traversal, `messages get --ref REF --json` for metadata-only detail, `messages get --ref REF --view plain --json` for normalized body text, and `messages raw --ref REF` for the unmodified RFC 5322 message.

Account entries also expose `type`, `display_name`, `discovered_sender_identities`, and `configured_sender_aliases`; `email_addresses` is their compatibility union. An explicit binding reports `identity_coverage.source:"account_binding"` and `state:"configured"` even when Sent history is empty. Binding failures such as `account_binding_ambiguous`, `account_binding_missing`, and `account_binding_stale` are typed and must be resolved before sending or mutation.

Treat the CLI as a standards boundary, not a proprietary content pipeline. Structured responses are schema-versioned JSON; exact messages are RFC 5322/MIME; recipient strings follow mailbox-address syntax; timestamps are RFC 3339; attachment metadata exposes MIME media type and decoded size; saved files contain the decoded MIME-part bytes and return SHA-256. Attachment IDs are opaque deterministic MIME-part paths and must be passed back unchanged. Attachment transfer-decoding errors and declared `X-Apple-Content-Length` shortfalls mark the containing message incomplete while retaining recovered bytes and healthy attachment metadata. MIME reads also enforce one aggregate per-message budget of 32 MiB decoded text, 4,096 visited entities, 64 nesting levels, 8 MiB retained metadata, and 128 MiB source bytes. A budget stop preserves validated data, keeps `content_complete:false`, and records `mime:budget:text_bytes`, `mime:budget:parts`, `mime:budget:depth`, `mime:budget:metadata_bytes`, or `mime:budget:raw_bytes` in `missing_parts`; cancellation records `mime:canceled` and remains an error. If `content_complete` is false, do not substitute Mail scripting convenience text or infer missing bytes; inspect `missing_parts`, use `messages raw` when available, or report the message as incomplete.

When local message content is parseable but IMAP hydration fails, `messages get` and `drafts open` return exit `1` and keep the partial `data.message` in the failed JSON envelope (`ok:false`). Inspect `data.message.hydration` for `state` (`failed` or `canceled`), attempted source, sanitized local and remote causes, and remediation; also require `content_complete:false` before using the retained content. Human mode prints the retained content and the same safe diagnostic fields, and canceled hydration remains an error that must be retried only when the operation can finish.

List, filter, and search page sizes are `1..25`. Use `--limit 25` for throughput and continue with `data.page.next_cursor`; the cursor is query-bound and page-size independent but bound to `data.page.coverage.index_revision`. Pagination is `best_effort`, not snapshot isolation. References and cursors are opaque compact tokens with bounded decoding; supported older tokens remain readable, while unknown versions, malformed lengths, unknown flags, and trailing bytes fail closed before store or provider I/O. Restart without a cursor after `search_cursor_stale` or `search_index_changed`. Never invent a larger page size.

Use `messages filter --json` for typed constraints and `messages search --query TEXT --json` only when body terms are required. Both accept `--sender`, `--recipient`, `--subject`, `--after`, `--before`, `--read true|false`, `--flagged true|false`, `--attachment true|false`, `--account REF`, `--mailbox REF`, and `--exact-count`; body search additionally accepts `--max-messages` and `--max-bytes`. Metadata-only pages fetch the requested page plus one continuation candidate and run no candidate-count query by default; their `candidate_messages` is the observed lower bound and `candidate_messages_exact` becomes true only when no continuation candidate remains. Attachment-only searches are catalog-fast: a positive catalog count decides both filter directions without reading the message; catalog-zero candidates still read authoritative MIME because the catalog can lag. A negative result is exhaustive only when `data.page.coverage.complete` is true. Body search is a stateless on-demand scan; narrow its scope and set `--max-messages` or `--max-bytes` when the task is bounded. A full result page stops loading further candidate chunks, keeps the cursor at the last classified candidate, and uses only a bounded keyset lookahead when the loaded prefix is fully classified. Its default `candidate_messages` is an observed lower bound unless `candidate_messages_exact` is true. Use `--exact-count` when an exact total is required; it adds one bounded count probe scoped after the current cursor and covering at most `max-messages + 1` rows for body searches or the normalized default bound for metadata filters, and fails with `search_count_limit_exceeded` above that bound. `--max-messages` defaults to 50,000 and is capped at 100,000; it bounds body candidate scanning and metadata exact-count work. Continue with `data.page.next_cursor`. Inspect `data.page.coverage.complete`, candidate-count exactness, partial and missing source counts, and scan bounds before claiming exhaustive results.

For repeated independent reads, received-attachment saves, or message marks, use `mailcli batch --input - --json` with one JSON object containing `operation`, an ordered `items` array, and optional `concurrency` from the capability limits. Every item needs a unique trimmed `id` and a store-bound `ref`; attachment saves also need an opaque `attachment_id` and an absolute new `output_path`, while marks need at least one explicit `read`, `flagged`, or `junk` value. The invocation reuses one store and transport graph, validates all IDs, refs, output parents, existing paths, and destination conflicts before dispatch, and returns items in input order under `data.batch_result`. Check `completed`, `failed`, `skipped`, and `uncertain` counts. A canceled item that never started is `skipped`; an active canceled mark is `uncertain` and must not be retried. There is no automatic retry. Submit a later batch only for explicitly selected failed items with `error.retryable:true`; never replay successful or uncertain mutations.

MailCLI owns no search index and has no refresh command. Its supported reads already use Mail's local store without Apple Events. Never bypass it with raw SQLite, direct private-file traversal, Mail `whose`, or UI-coordinate automation.

Treat returned message references and cursors as opaque and short-lived. MailCLI binds them to the current store and mailbox membership. After copy, move, delete, or provider synchronization, list or search again for a fresh reference before the next action.

## Compose and mutate

Pass long bodies, recipients, and attachment lists as structured JSON through `--input -` or an input file, or use repeatable `--to`, `--cc`, `--bcc`, and `--attach` flags with `--body` or `--body-file`. Never mix JSON input and terminal-native flags. Always include the JSON `body` key, including when an empty body is intentional. Use `--format plain|markdown|html`; Markdown and HTML are stored with a canonical plain-text representation. HTML retains semantic typography, headings, links, lists, preformatted blocks, and table elements. Only absolute `http`, `https`, or `mailto` link targets and anchor titles survive; CSS, `style` attributes, event handlers, forms, media, scripts, SVG, MathML, templates, and remote resources are removed. Images are not embedded, while `alt` text remains in the plain alternative. Inspect `content_diagnostics` on rich draft responses for deterministic value-free records of removed elements, attributes, URLs, styles, or resources. The plain alternative keeps non-redundant absolute link targets as `(URL)`, preserves `<pre>` and `<code>` whitespace, emits indented list markers and pipe-delimited table rows, and omits unsafe links and active subtrees. Incoming HTML message parts use the same conversion. Keep To, CC, and BCC distinct and never repeat one address across roles. Use an explicit configured `from` address when account choice matters; add `--account REF` to bind that sender to one stable Mail account. Draft attachment paths must be absolute. Fingerprinting opens only regular files without following a replaced final symlink or blocking on a special file, reads at most the remaining attachment budget plus one byte, and rechecks descriptor identity and path size after hashing. Create, update, and handoff verification honor caller cancellation; canceled work does not accept a partial fingerprint or dispatch a handoff. Respect the local-draft limits: 64 KiB subject, 4 MiB body, 200 total recipients, 100 attachments, and 512 MiB attachment bytes.

Create a local review draft with `mailcli drafts create --to recipient@example.com --subject Subject --body 'Readable plain text.' --json` or structured JSON. Use `drafts preview --ref REF --format plain|source|html`, `drafts edit --ref REF`, `drafts inspect --ref REF --json` (metadata by default; add `--view plain` or `--view full` for stored body variants, or `--export /absolute/new/path` for a verified body file; a consumed send receipt appears under `data.send_receipt`), or full-replacement `drafts update`. These operations never contact Mail.app and never send mail. A canceled external editor and all descendants owned by that invocation are terminated before the command returns, and the original draft remains unchanged.

After draft workflows, check `drafts list --json` for leftovers: list entries are summaries (ref, subject, recipients, timestamps, format, attachment count, attempt state; never body content, use `drafts inspect` for content). Corrupt or unreadable draft files appear as minimal `state_error` entries when the path is still present; inspect and send fail closed with the affected path, while transient missing-file races remain skippable. Entries with `ever_sent:false` and a high `age_days` are stale never-sent drafts. Remove them with `mailcli drafts prune` (dry run by default; add `--confirm` to delete exactly the listed drafts and expired terminal send receipts, `--older-than <days>` to change the stale-draft threshold; terminal receipts use fixed 30-day retention; values below 1 day are rejected as `invalid_argument`). Prune never touches drafts with send or save attempts or receipts that still have an unresolved claim; reconcile or discard those explicitly instead.

On the verified Mail 16 host, never invoke `drafts save` for a new draft; capabilities report `new_native_save:"rejected_before_mail_contact"`, and it returns `compose_automation_unsupported` before Apple Events. Mail 16 live tests lost reviewed body and recipients, rejected scripted attachments, and created phantom drafts. If `drafts list --json` or `drafts inspect --json` shows a historical `save_attempt`, the only safe recovery is `mailcli drafts save --ref REF --json`; that path is reconcile-only, never starts a new compose, and retains the local draft when exact observation is unavailable. For a new local draft with no explicit From, CC, or BCC, `drafts handoff --ref REF` may open Apple's visible Compose Email service. It retains the local draft and never sends. A successful handoff means the sharing-service delegate confirmed a visible compose request, not that a message was sent; live Mail 16 verification showed the compose window before returning success. Attachment fingerprints are verified before handoff. A timeout or delegate failure is an unknown handoff outcome and must not be retried blindly. It fails if Mail.app is not the default email application, preventing an accidental browser or third-party mail-client launch. Add sender, CC, or BCC manually in Mail.app when needed. Never use handoff for reply/forward threading, and never bypass the safety gate with raw AppleScript, JXA, or a direct provider API.

For replies and forwards, use a fresh store-bound message reference from list or search, then create a local review draft with `messages reply --message MSG_REF --input - [--all] --json` or `messages forward --message MSG_REF --input - --json`. Derivation is automatic: subject gains `Re:`/`Fwd:`, every valid address in Reply-To becomes a reply target in header order, and From is used only when Reply-To is absent; a malformed or partially parsed Reply-To fails with `invalid_message_source` instead of silently falling back. `--all` promotes the other To/CC recipients while excluding all reply targets and final To recipients, and sent replies and source-bound forwards carry a canonical In-Reply-To/References chain. Valid angle-bracket Message-ID entries remain in first-seen order with duplicates removed, the direct parent appears once at the end, and the final chain is capped at 20 entries; malformed entries are rejected. Manually persisted drafts without source threading remain unthreaded. Explicit input fields win over derived ones, including explicit empty `subject`, `to`, or `cc`; omit a field to derive it. Native recipient flags accept an empty value for explicit emptiness, while JSON uses `""` or `[]`; final To/CC roles are deduplicated by normalized address before validation. A forward input must include at least one explicit To, CC, or BCC recipient. Inspect the result. The sent reply threads at the MIME level, but quoted original content and original attachments are never materialized; only your own body is sent.

Use `drafts open --message MSG_REF --json` to inspect an existing persisted Mail draft without opening an editor. Keep edits in the local review draft because Mail 16 has no reliable headless in-place editor.

List received attachments with `attachments list --message MSG_REF --json`. Save one with `attachments save --message MSG_REF --attachment ID --output /absolute/non-existing/path --json`; the command never overwrites an existing path, pins the output parent and temporary/published file identities, applies `0600` through the owned descriptor, verifies the exact published bytes, and returns byte count plus SHA-256. `attachment_changed` means ownership was lost during publication or cleanup; the command preserves the replacement and never removes an unverified path.

Use explicit `messages mark`, `messages copy`, `messages move`, `messages delete --confirm`, and `sync` commands. Mark, move, copy, and delete execute over IMAP directly without launching Mail.app or consulting the Apple Events fallback. A mutation targeting a degraded account fails with typed `account_degraded` and the account's `degraded_remediation`; only a global SQL or schema failure returns `account_catalog_incomplete` with remediation to run `mailcli doctor`. They load the same Keychain credential as send; if it is missing they fail with `smtp_credentials_missing` and remediation naming `mailcli send setup`. Each mutation returns typed `server_truth` evidence (command, server response, mailbox, target mailbox, UID); duplicate exact Message-ID matches add `duplicate_matches` while keeping the last verified UID, and substring candidates are discarded before any target is accepted. COPY also returns an operation identity, outcome, destination identity, and COPYUID mapping when the server provides one. A lost or incomplete COPY reply returns `imap_copy_outcome_unknown`; reconcile the exact destination Message-ID first, and never retry when it is already present, duplicated, or has a changed UIDVALIDITY. MOVE fallback evidence exposes proven phases in `completed_effects`, including `copy`, `source_flag`, `uid_expunge`, and `cleanup_deferred`; a partial or unknown result requires source/destination reconciliation before another mutation. The local store staleness model: mutations apply immediately on the IMAP server; the local read store updates on Mail.app's next background sync. `mailcli sync --check [--account REF] [--json]` compares the union of local and server mailbox identities over IMAP without launching Mail.app. Each `data.sync_check.mailboxes` entry reports `state` (`matched`, `local_only`, `server_only`, `inaccessible`, or `unresolved`), `local_messages_available`, `server_messages_available`, and the exact `server_name` when known. Matched entries carry a truthful count delta only when the local count is available; a cached local identity without a count remains unresolved with server evidence and no delta. A missing side keeps its count unavailable and adds a typed failure. `data.sync_check.complete:false` means partial coverage, never verified: `data.sync_check.failures` names every uncovered account or mailbox with its typed code, including missing local mailboxes and failed server LIST or STATUS. Default incomplete checks retain exit 0 for compatibility. Scripts that require exhaustive coverage must add `--require-complete`; exit 3 then carries the same `ok:true` incomplete result, while runtime errors remain exit 1 with `ok:false`. `mailcli sync` without `--check` asks Mail.app to synchronize the local store and requires Mail.app running; prefer `--check` when only server deltas are needed. Local-only mailboxes (On My Mac) reject mutations with typed code `local_only_mailbox`. Mark, move, and delete reject draft messages unless the user explicitly authorizes draft mutation, every editor for that draft is closed, and `--allow-draft` is supplied; delete still also requires `--confirm`. A server without UID MOVE uses UID EXPUNGE when available; otherwise MailCLI defers EXPUNGE when other deleted UIDs are present and reports `server_truth.expunge_branch:"deferred"` with `foreign_deleted_count`. If delete returns `message_already_trashed`, stop; restore it in Mail or use Mail.app to empty the trash. Do not reinterpret archive as delete or delete as permanent removal. Never send or delete without explicit user authorization. Moving, copying, marking, and `sync` without `--check` mutate live Mail state, so require a user request that covers the action.

Attachment saving reuses the verified size, SHA-256, and bound regular-file identity evidence returned by the authoritative writer after checking the temporary and published path identities, so an unchanged publication is not reread solely to reconstruct metadata. Visible draft handoff performs a metadata preflight and one authoritative staging read that verifies the recorded size and SHA-256 before passing the private snapshot to Mail.app.

Never loop live mutations rapidly. Let each MailCLI command finish and inspect its typed result before issuing the next command. The CLI reuses account and mailbox resolution within an invocation and bounds message pages to 25; agents must not add their own polling or raw Apple Events around it.

## Send

Sending is autonomous and never involves Mail.app: `drafts send --ref REF --confirm --json` submits the reviewed draft over SMTP and mirrors it into the account's Sent mailbox over IMAP. There is no Mail.app launch, no Apple Events, no compose window, and no Automation or Full Disk Access requirement; the first keychain read may show one macOS consent prompt.

Setup uses `mailcli send setup --from ALIAS [--account REF] [--credential-account LOGIN]`. It stores the app-specific password in the macOS Keychain under `LOGIN` (or under `ALIAS` when no credential identity is configured) and atomically records the alias binding when `--account` is supplied. Re-running setup for an existing binding preserves its credential identity unless `--credential-account` is explicitly changed. `--remove` deletes the selected credential and retains the binding for safe reconfiguration. MailCLI never displays, logs, or returns the password. Never ask the user to paste a password into chat or pass one on the command line; direct them to the setup command.

The send flow resolves provider endpoints from the From address, loads the keychain credential, builds the RFC 5322 message with a locally generated Message-ID, submits it over SMTP with STARTTLS, and appends it to the Sent mailbox over IMAP. Short protocol commands and final replies use 30 seconds; encoded SMTP DATA and IMAP APPEND transfers use 30 seconds plus one second per MiB at a 1 MiB/s floor, capped at 15 minutes, and the caller context takes precedence. Direct transport supports only Gmail (`gmail.com`, `googlemail.com`) and iCloud (`icloud.com`, `me.com`, `mac.com`); other domains fail with `transport_unsupported_provider` before credentials are stored or network connections begin. A confirmed result reports compatibility outcome `sent` with canonical `submission_accepted:true` only for the final SMTP 2yz response after DATA and `sent_copy_observed:true` only for exact Sent persistence; neither field confirms recipient delivery. After terminal evidence is recorded, MailCLI writes a bounded private `<REF>.send-receipt` sidecar before removing the draft and transient claim; it contains timestamps, final outcome, canonical submission and Sent-copy booleans, SMTP response, Message-ID, Sent mailbox, optional UIDVALIDITY/UID, and append state, never body or attachment bytes. Repeating `drafts send` or `drafts reconcile` for a consumed reference returns the immutable receipt without transport writes, and `drafts inspect --ref REF --json` exposes it under `data.send_receipt`; it expires after 30 days and `drafts prune --confirm` removes only expired receipts with no unresolved claim or draft. If SMTP accepted the message but the Sent mirror failed, the outcome is `sent_mirror_pending` with `submission_accepted:true` and `sent_copy_observed:false`: recipient delivery is unverified, so never resubmit it; the retained claim stays reconcilable through `drafts reconcile`. After DATA, a syntactically complete SMTP 4xx or 5xx final reply is a definitive `smtp_rejected`; `error.message` retains the full reply and enhanced status, 4xx is transient and may be retried only by a later explicit send after the server condition is resolved, and 5xx is permanent and requires correcting the message or recipients first. A missing, truncated, malformed, timed-out, or otherwise unreadable final reply remains `smtp_submission_unknown`; retain the claim and never retry automatically. Missing credentials fail with `smtp_credentials_missing` and remediation naming `mailcli send setup`. An unsupported or malformed From address fails with `transport_unsupported_provider` or `invalid_address`. Stop and tell the user; do not invent endpoints or edit MailCLI source. Other typed codes surface verbatim: `smtp_auth_failed`, `smtp_rejected`, `smtp_tls_failed`, `smtp_timeout`, `smtp_transfer_timeout`, `smtp_submission_unknown`, `imap_connect_failed`, `imap_auth_failed`, `imap_sent_mailbox_not_found`, `imap_ambiguous_mailbox`, `imap_append_failed`, and `imap_timeout`. Sending requires explicit user authorization and `--confirm`; never send without a user request that covers the action.

For a bound draft, send resolves `from` through the explicit account binding and uses its credential identity for SMTP and IMAP. Without `--account`, an unambiguous alias binding is used; an ambiguous alias fails closed with `account_binding_ambiguous`, while an explicit account with no binding fails with `account_binding_missing`. The binding must still match the current local account catalog and supported provider; removed or changed accounts return `account_binding_stale`.

If a send crashes after SMTP submission acceptance, the retained claim carries a Message-ID, envelope fingerprint, and versioned MIME fingerprint, so `drafts reconcile --ref REF --json` resolves it without resending: exactly one Sent-mailbox match is fetched and checked against the claimed Message-ID, sender, recipients, subject, body, and complete MIME fingerprint (plain/HTML alternatives plus ordered attachment type, name, decoded size, and SHA-256) before upgrading the claim to `sent`; this direct path uses IMAP and local claim state without opening the Mail store and proves a Sent copy only, never recipient delivery. Duplicate matches, identity mismatches, or unreadable candidates fail closed with reconciliation evidence. Once terminal evidence is persisted, the compact private send receipt is written before draft cleanup, so a crash in that window or a later retry returns the same attempt and Message-ID without another SMTP or APPEND. Absence returns `send_outcome_unverifiable` with the Message-ID and manual remediation, and retries stay blocked either way (absence in Sent does not prove non-delivery). Legacy claims with a store observation baseline remain store-backed; claims without a Message-ID stay blocked with `send_reconcile_unavailable`; claims with a Message-ID but without a versioned MIME fingerprint stay blocked with `send_identity_unverifiable`; discard them explicitly after manual verification.

Send evidence matrix: `sent` means `submission_accepted:true` and `sent_copy_observed:true`; `sent_mirror_pending` means `submission_accepted:true` and `sent_copy_observed:false`, with recipient delivery unverified and no SMTP resubmission; `outcome_unknown` and an explicit SMTP rejection keep both canonical fields false. A complete final SMTP 4xx/5xx is explicit `smtp_rejected`; an incomplete or unreadable final reply is `smtp_submission_unknown` and retains the claim. `accepted_by_mail` and `sent_store_observed` remain compatibility aliases and must not be read as recipient-delivery confirmation.

## Output handling

Keep message bodies and addresses out of logs and summaries unless the task requires them. Detail JSON uses validated projections: `--view metadata|plain|full` selects a named view, `--fields field1,field2` selects optional fields from `data.capabilities.limits.output_projection` while identity, completeness, and operation-state evidence remains, and the two flags cannot be combined. `messages get` and `drafts inspect` default to metadata, so request `--view plain` when body text is needed; `drafts create`, `drafts update`, `drafts edit`, `messages reply`, and `messages forward` return the canonical plain draft body by default. `--max-bytes` defaults to 1 MiB and returns `output_too_large` instead of truncating a JSON envelope. `messages get`, `messages raw`, and `drafts inspect` support `--export /absolute/new/path`: the complete body or raw source is written with exclusive mode-0600 creation, verified for identity, size, and SHA-256, and omitted from JSON in favor of `data.content_export`. Export requires complete normalized content and a new absolute destination. Every projection retains identity and completeness or operation-state evidence; a failed hydration keeps the safe `data.message.hydration` diagnostic and recovered content when no export was requested. Preserve exact raw output when the user asks for RFC 5322 source. For human-facing drafts, use `drafts preview` and the stored canonical representations. Visible handoff uses sanitized rich content when present; a successful handoff proves only that macOS accepted the visible compose request, never that the message was sent.

Check `content_complete`, `missing_parts`, and search `coverage` before making completeness claims. Targeted fallback content hydrates over IMAP (`content_source: "imap_raw"`) without launching Mail.app or sending Apple Events. If the binary lacks a required command or returns an unsupported store profile, stop and report it. Do not bypass MailCLI with direct store access, raw AppleScript/JXA, or UI coordinates.

## Error contract

Every `--json` response is a single envelope:

```json
{"schema_version":1,"ok":true,"command":"accounts.list","data":{"accounts":[],"complete":true,"identity_coverage_complete":true},"error":null}
```

On failure:

```json
{"schema_version":1,"ok":false,"command":"accounts.list","data":{},"error":{"code":"operation_failed","message":"..."}}
```

Exit codes: `0` = success, `1` = runtime/operation error, `2` = usage/argument error, `3` = only a valid incomplete `sync --check --require-complete` result. Exit 3 keeps `ok:true` and `error:null`; inspect `data.sync_check.complete` and `failures`. Always check the envelope, not just the exit code.

Generic error codes and remediation:

- `unknown_command` — the command ID is not recognized; run `mailcli capabilities --json` for the authoritative list.
- `invalid_argument` — a flag or positional argument is wrong (exit 2); the message names the problem.
- `invalid_input` — structured input (stdin/file JSON, body, format) is malformed; the message names the field and constraint.
- `missing_required` — a required flag was omitted; the message names the flag (e.g., `missing required --ref`).
- `confirmation_required` — the action needs `--confirm` after explicit user authorization.
- `operation_failed` — a runtime failure (store, IMAP, SMTP, Mail.app); inspect `error.message` and any typed code in the message. Do not blindly retry; diagnose the cause first.

Typed transport and store codes (`smtp_auth_failed`, `imap_connect_failed`, `mail_busy`, `mail_not_running`, `local_only_mailbox`, `account_degraded`, `account_catalog_incomplete`, `account_reference_corrupt`, `account_reference_version_unsupported`, `account_reference_invalid`, `account_disabled`, `account_identity_missing`, `account_binding_invalid`, `account_binding_unavailable`, `account_binding_provider_mismatch`, `account_binding_ambiguous`, `account_binding_missing`, `account_binding_stale`, `account_binding_account_degraded`, etc.) are documented in the relevant sections above and surface verbatim in `error.message` or `error.code`. When a typed code appears, follow its specific remediation rather than retrying with different flags.
